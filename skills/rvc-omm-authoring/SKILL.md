# RVC 圖文寫作

讓讀者先看懂結論與全貌，再讀必要細節。複雜方案先用圖形承載流程、分工與差異，文字補原因與證據；不是把長段落搬進卡片或表格。簡單結論仍用短文，不硬湊圖量。

## 先確認正本與範圍

- 先讀所在環境的全域規範，再讀目標 RVC repo 的 `AGENTS.md`。主機以 `/root/AGENTS.md` 為規範入口時，讀完整檔的 RVC、Secret 紀律、QA 雙閘與瀏覽器配額各節，不只看已自動載入的部分；該主機的 RVC 專案在 `/root/kim-rvc-site`。其他環境找當地的全域規範與實際專案，不假設這些路徑存在，不猜發布命令。
- 發布前依 RVC repo 的〈部署架構〉確認所在機器就是發布主機；不是或判斷不了，就停在候選，回報「未發布」。
- 上層正本決定何時用 RVC 與資料能否公開；專案正本決定標記、日期、更新、圖片、重建與連結。以當次使用者要求和現行正本為準，本技能不另外維護一套強制發布規則。
- 使用者只要討論、檢查或草稿，就停在該範圍。已授權發布時直接完成，不重問同一項授權。寫文章不授權執行文中的操作、搬遷、修改共用站台設定或推送 Git。
- 修改前確認 Git 與目標檔現況。修改舊文保留 URL、作者與未涉及內容，按專案規範處理新 block／更新時間；不為套新版範本重排整篇。

## 先讓圖說清楚全貌

寫長篇方案、比較或調查結果前，先找出讀者必須理解的關係，再安排圖文。開頭用一句話說結論，接能看見核心關係的總覽；不要先鋪完整背景與逐項說明，最後才補一張摘要圖。只有短結論或沒有可視關係的內容，不為符合形式而畫圖。

| 讀者要理解的事 | 優先形式 | 範本 |
|---|---|---|
| 先後順序、輸入輸出、條件與去向 | 流程圖或決策圖 | flow（2–6 步，判斷可省） |
| 走到哪裡、每一站的狀態 | 路線圖 | road |
| 誰負責什麼、交付給誰 | 分工圖或泳道圖 | lanes |
| 多個能力如何組成、共用與重疊 | 關係圖或交集示意 | zones |
| 改了什麼、前後如何不同 | 前後對照圖 | before-after |
| 同一批項目的少數可比差異 | 精簡比較表；有程度或數量資料時才用圖表 | comparison |
| 結論、理由、限制、精確來源 | 短段落或條列 | prose |

每張圖只回答一個問題。節點用短標籤，箭頭說明流向或交付，區域表示分工或共同範圍；不要只有裝飾圖示、編號及相鄰文字框。卡片與表格若每格仍需讀一段話，應重組資訊，而不是把它們計為已完成圖形化。具體做法見 [版面與範本](references/layout.md)。

主流程、重要分支、比較選項與決策所需前提預設可見。補充證據可以分層，不能把改變結論的風險或條件藏進收合區；不靠「下一階段」或切換按鍵才拼出全貌。互動可用於放大、導覽、篩選或試算。手機優先重排，避免縮字或縮整張圖到看不清楚；重要關係也用文字標籤表達，不只靠顏色。

圖文互補：圖已說清楚的步驟不再逐段重述；圖外只補原因、例外與來源。技術事實、已完成狀態和規劃須有明確標記，範本示例不是任務證據。圖表的數據與關係都要有來源，不為視覺效果捏造比例、依賴或能力限制。

## 製作候選

新頁、補 block 或獲授權的版面調整，讀 [版面與範本](references/layout.md)。先依內容決定圖形，再選可用片段；範本的步數與分支數不是內容限制，不要求每種片段都用。

- 新頁先依專案正本指定的草稿區製作候選；本機檔案不等於已發布，不沿用已退場的監看目錄或發布入口。
- 沿用目前站台的字型、語意色彩和元件。CSS 限定於本篇唯一 ID；不要改共用模板來配合單篇範例。
- CSS 一律用技能目錄的 `python3 scripts/rvc_figs.py css <文章ID> <圖型…>` 產生後整段放進 base 的 `__CSS__`；不要逐字重打或改片段 CSS，改了就不能免驗。範本以外的形狀可以自己寫，但要驗畫面。
- 狀態固定用四個詞：已完成、進行中、規劃中、待決，寫法見〈版面與範本〉；不另創狀態詞或配色。
- 發布前按 repo 正本核對 HTML 結構、作者／主題、即時日期、圖片與更新規則。新單篇從 base 起頭；替用本範本的頁補內容用 block 片段。

## 驗證與交付

依上述全域規範判斷 QA 時點與免審範圍；使用者要求前後 QA 時照做。需要審的候選在正式發布前通過；不能用本技能自行豁免。

先做閱讀檢查：只看標題、總覽與圖內標籤，能否回答本篇核心問題、看出建議與必要條件？逐一移除圖文重述，檢查是否仍靠長段落或長文字表格才能懂主要關係；不能以圖的張數、面積比例或 HTML 標籤數宣稱通過。

發布前跑技能目錄的 `python3 scripts/rvc_figs.py check <候選.html>`，並自己核對 HTML 跳脫與 block 的屬性順序：

- `RESULT: 錯誤`：佔位符、文章 ID、範本結構或順序、判斷結果、泳道座標或比較表標籤寫錯，修完重跑。
- `RESULT: 免驗`：只用了沒改過的片段 CSS 與範本 class，沒有圖片、SVG、嵌入或腳本，圖的數量與字寬都在〈已驗範圍〉內，而且片段 CSS、檢查工具、驗證固定頁與外框檔從最近一次範本驗證後都沒變。可以不開瀏覽器，回報寫「結構已查、範本免驗」。
- `RESULT: 要驗畫面`：照下面在真實 RVC 外框驗桌面與手機，不能只用裸 HTML。使用者要求看畫面時也驗。

工具只認範本驗證紀錄。紀錄不存在或過期（技能或外框改過），就先照〈版面與範本〉的〈重驗範本〉驗完再寫紀錄，或直接驗這一篇。不為了免驗把內容硬塞進範本形狀，也不改寫工具結果。所在機器沒有真實外框可驗時標示「畫面未驗」。驗畫面時：

- 讀當前模板／生成頁，保留外層、共用 CSS、發布日期和必要腳本。核對 scope 選擇器在真正 DOM 上命中。
- 依所在機器的瀏覽器配額規則啟動；有共用排隊入口就經由入口並依正本盤點，沒有既定規則時一次只開 1 個瀏覽器並在回報講明。無名額時不跳過必要檢查先發布。
- 量測寬度、實際間距和手機兩側總留白；確認無橫向溢出、圖文與主要分支預設可見、圖中文字可讀。新互動另驗鍵盤與狀態回饋。
- 桌面 1350px、手機 450px／375px 為新版面起點；改響應式規則時加驗使用中斷點兩側。內容量、長標題或任務要求可能需要其他尺寸。看截圖，不只看程式斷言。

必要 QA 與候選檢查通過後，在已授權範圍依專案正本發布，確認生成頁與受測候選一致；屬於須驗畫面的情況，再核對正式生成頁的桌面／手機效果。只用範本 CSS（檢查判免驗）的頁不必記 UI changelog；有自訂 CSS 或新版面時，照專案規範記一行。

回覆給完整 RVC HTTPS 連結及簡短結論。分清「結構已查、畫面未驗」「畫面已驗」「已發布」「使用者已接受」；本機來源站驗過不等於已驗外部登入流程。驗證記錄與截圖留 `.temp/`，需要給截圖時用 Markdown 嵌圖或已授權的 RVC 頁，不在聊天只貼圖片檔路徑。
