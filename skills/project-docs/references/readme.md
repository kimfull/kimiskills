# README.md：專案介紹與使用入口（選配）

只有主人要求才建立或更新；沿用現有 README 的位置與大小寫，沒有才建立 `README.md`，不另造小寫副本。分組指令（見 [SKILL.md](../SKILL.md#分組指令)）包含 README 時，已有就更新，缺少且有符合下述寫入門檻的實際內容就補建，不建立空白樣板。保持既有讀者與用途，不強迫把成熟專案 README 重排成同一種版面。

## 檔頭必填

- 專案／工作主題。
- 最後更新時間。
- 內容確認截至：實際時間與確認範圍；不同事項分別記錄，未確認須明說。
- 對照 repo／工作樹、Git 基準完整 commit；非 Git 或未知如實標明原因。
- 確認當下的工作目錄狀態：clean／dirty／unknown；dirty 另列相關路徑與安全摘要。沒有可比對證據時，不把 SHA 當成當時內容的完整快照。

時間格式與有效性核對依 [日期與 Git 核對](freshness.md)。可另外列建立時間，但不可猜測；它不取代更新與確認時間。

## 寫入門檻

README 寫進去要謹慎，寫了就要完整。建立或更新 README 時，主人沒有逐項交代、要自行判斷該不該寫的每一則資訊，同時符合三項才寫入；分組指令與主人直接說「更新 README」都一樣：

1. **已定案**：主人裁定，或主人驗收通過。只通過測試或 QA、主人還沒看過的不算。
2. **讀者用得到**：改變了專案用途、使用方法或資料入口。
3. **不會很快失效**：不是當次進度、試驗中的做法或暫時狀態。

- 候選不只本輪對話：已有 README 時，把上次內容確認之後、已記在 status 的定案與驗收結果一起看；新建時從本專案已核實的定案與驗收結果判斷。先前沒過門檻、現在已定案的這時補進來。
- 符合的把那一段寫完整：讀者不看對話也能照做，指令與路徑都有依據。不符合的不寫進 README：status 在本次範圍內就寫進 status，否則回報沒寫入。
- 分組指令下沒有任何一則符合時，既有 README 不動、不刷新時間，回報「README 無需更新」；缺少的 README 不補建，回報「README 尚無符合門檻的內容，未建立」。
- 主人直接說「更新 README」時，仍重查既有內容，重查過的才更新內容確認時間；新內容一樣過門檻。
- 主人明確交代要寫進 README 的內容照寫。既有敘述已不正確時（不論哪一輪造成），依本檔末段修正或標記，不受門檻限制。

## 內容

1. **用途與範圍**：這是什麼、誰會使用、主要功能及限制；不假設讀者看過對話。
2. **使用方法**：按專案需要列環境／版本需求、準備步驟、操作指令、預期結果、常見問題。不適用的項目省略；每個指令與路徑須有依據，未實測明說。設定範例只放名稱與安全占位內容，不放秘密或個資。
3. **資料入口**：連到實際存在的重要目錄、手冊、todo、status、handoff 或永久知識文件；沒有的文件不假造連結，也不為湊入口而建立。
4. **分工**：詳細待辦留在 todo，當次進度及驗證結果留在 status，新對話接續位置與必要背景留在 [handoff](handoff.md)；工作規範仍以 AGENTS.md 為正本。README 只保留讀者使用專案所需的摘要與連結，不複製整套規則或另一份即時進度。

過時的操作說明須修正或清楚標記，不讓讀者把歷史指令當現行方法。保留必要歷史，但放在目前有效說明之後。最後更新日期變新，不能讓未重查的內容確認時間跟著變新。
