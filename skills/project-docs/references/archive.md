# 歸檔：把 todo 與 status 的舊內容搬出主文件

主文件只會越寫越長，每次讀取都多花時間。這裡的歸檔是把不再影響接手的舊內容**原文搬到**同目錄的歸檔檔：不是刪除，不是改寫成摘要，也不是寫進 永久知識庫。README 不適用：過時的使用說明是修正或標記，不搬走。

## 何時做

- 只在主人要求更新該份 todo／status 時順帶檢查；讀取、核對或討論時不搬。
- 門檻依 SKILL.md。達門檻時搬較舊的，把最近完成的 5 筆留在主文件，讓接手者看得到剛做完什麼。未達門檻不搬；主人指名要搬或另訂門檻時照主人的。
- 歸檔檔算該份主文件的一部分，不算另一份文件：只要求 todo 就只動 todo 與它的歸檔檔，不順帶整理 status。

## 搬到哪

- 與主文件同目錄，檔名為主文件檔名加 `-archive`，沿用原大小寫與副檔名（`todo.md` → `todo-archive.md`、`STATUS.md` → `STATUS-archive.md`）。一份主文件只有一份歸檔檔，不按日期拆檔。
- 歸檔檔檔頭列專案／工作主題、對應的主文件、建立時間、最後更新時間，並註明「歷史紀錄，不代表現況」。時間格式同 SKILL.md。

## 可以搬與不能搬

| 文件 | 可以搬 | 不能搬 |
|---|---|---|
| todo | 已勾選且符合驗收條件的任務；已取代、已取消的計畫 | 未完成、部分完成、受阻、待驗證的任務；已勾選但證據不足的；待主人決定事項；仍被未完成任務列為前置的項目 |
| status | 已完成且不再影響後續工作的事項；已被較新結果取代的驗證紀錄 | 進行中、尚未開始、受阻／待確認；決策紀錄（含已否決與已推翻）；現場殘留；下一個接手動作；仍有效的限制與已知問題 |

搬之前先在專案內找有沒有文件指向要搬的章節或編號（AGENTS.md、README、另一份交接文件）；被引用的不搬。拿不準就留在主文件。

## 怎麼搬

1. 寫入前重讀主文件與歸檔檔；被別人改過就依最新內容調和。
2. 比對歸檔檔：同一筆已經在歸檔檔裡（上次中斷，或另一個工具搬過）就不再寫一次，只從主文件移除。
3. **先把新的一批附加到歸檔檔檔尾、確認寫入成功，再從主文件移除**；順序不可反。只附加，不重寫歸檔檔既有內容。每批開頭加一行標題，寫歸檔時間與範圍（代號或日期區間）。
4. 原文照搬，保留原代號、勾選狀態、日期、確認時間與「沿用舊紀錄」之類的標註；不改寫、不合併、不補寫當時沒有的結論。
5. 編號不可因搬動而改變。主文件用有序清單自動編號（`1.` `2.`）時，搬走項目會讓兩邊的預覽都重新編號：搬之前先把整份清單改成同數字的固定代號（原第 5 項寫成 `T5`），搬出與留下的都用同一個代號，並同步改掉主文件內的引用。這是原文照搬唯一允許的改動。
6. 主文件留一行指向歸檔檔，並寫已搬出的範圍；主文件裡仍引用被搬項目的地方改指向歸檔檔。
7. 主文件的最後更新時間照實更新；**狀態確認時間與各項原確認時間不因搬動而刷新**。

## 讀取與回報

- 歸檔檔預設不讀；需要追歷史、或主文件指過去時才讀。內容一律視為歷史紀錄，要當現況使用前依 [有效性核對](freshness.md) 重新確認。
- 不刪除、不精簡歸檔檔既有內容；要清掉得主人另外明說。
- 回覆時說明本次有無歸檔、搬了哪個範圍、歸檔檔位置。主文件在 Git 裡時，提醒歸檔檔是尚未追蹤的新檔，要跟主文件同一筆 commit，否則搬出去的內容只剩工作目錄那一份。歸檔本身不授權 commit、push 或同步第二大腦。
