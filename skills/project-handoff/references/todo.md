# todo.md：接下來要做的詳細工作計畫

先遵守 SKILL.md 的位置、日期、保留內容與授權規則。檔頭列專案／工作主題、建立時間、最後更新時間；舊檔建立時間查不到就寫「不明」。

- 開頭指出**最先要做的下一步**，再寫本次目標、工作範圍、已知限制與整體完成標準。
- 依優先順序與相依關係拆成可執行的任務，使用固定代號（T1、T2…）與核取方塊，代號建立後不重排、不重用，不靠有序清單的自動編號；既有檔沿用原編號方式。標明哪些可獨立做、哪些必須等前一項完成。
- 每項寫明：要做什麼、為什麼、涉及的檔案或功能、具體步驟、預期產出與如何驗收。接手需要的指令、測試或參考資料一併附上；尚未確認的路徑或做法不編造。
- 列出已知風險、阻塞原因、所缺資料與待主人決定的事項。分清「已定案待執行」與「建議／待確認」，不把尚未核准的建議當承諾。
- 只有確實完成且符合該任務驗收條件才勾選；部分完成、受阻或待驗證要明寫。若舊檔已勾選但證據不足，更新時標示待確認，不直接認定本次已驗過。
- 失效計畫標「已取代／已取消」、日期與原因；保留仍有效的工作與必要歷史。已完成與已失效的項目達門檻時，依 [歸檔規格](archive.md) 搬到歸檔檔，不直接刪除。
- status 有決策紀錄時，排任務前先讀；已否決的做法不排回待辦，要重提就列入待主人決定事項。
- 已有 status 時可連到其事實證據，todo 保留執行步驟，不把整份實際進度複製過來。新對話要從哪一步接續與協作注意事項留在 [handoff](handoff.md)，不另複製整份排程。只要求 todo 就不更新其他文件。

任務格式示意，可依工作調整，不留下空白欄位充數：

```markdown
- [ ] **T1** 任務名稱（已定案待執行／建議待確認；相依項目或可獨立做）
   - 目的與涉及範圍：
   - 步驟及參考：
   - 預期產出與驗收條件：
   - 阻塞或待決事項：
```

採用既有計畫前先依 [有效性核對](freshness.md) 確認前提，不能因為寫了待辦就直接執行它。
