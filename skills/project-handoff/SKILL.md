# 專案文件與交接

讓主人或接手者不必重讀對話，也能知道專案怎麼使用、接下來怎麼做、目前做到哪裡。本技能可供不同 AI 工具共用；遵守目前環境實際適用的使用者指令、AGENTS.md 與授權／保密規則，不要求固定作業系統或安裝路徑。若主機以 `/root/AGENTS.md` 作為規範入口，依其要求讀取；其他環境不要假設該路徑存在。

## 先判斷本次要求

- **讀取／檢查**：先依 [有效性核對](references/freshness.md) 讀取檔頭日期與版本，再採用相關內容；只報告確認結果、差異與限制，不修改文件或替它刷新日期。
- **寫／更新**：只有主人要求建立或更新指定文件時才寫入，不能只在對話列內容。先讀既有檔案、核對將沿用的事實，再讀下表對應規格。
- **討論／詢問格式**：只討論，不建立或更新檔案。只叫出技能但沒有工作內容時，從當前要求判定；仍不明確才詢問要讀取或更新哪份文件。
- 四份文件都按需要建立；只要求一份就只更新一份，要求多份才一起更新並保持一致，不為使用技能湊齊四份。
- **交接請求**：「寫交接」「交給新對話」未指定檔案時，依 [handoff 規格](references/handoff.md) 更新穩定交接入口；沒有才在專案根目錄建立 `handoff.md`。主人指定位置、既有大小寫與明確的同用途穩定入口優先；只有日期報告時保留報告，建立摘要入口，不每次另開日期檔。單純討論交接方式仍不寫入。

| 文件 | 用途 | 寫入時必讀 |
|---|---|---|
| README.md | 專案用途、使用方法與資料入口 | [README 規格](references/readme.md) |
| todo.md | 接下來要做的詳細工作計畫 | [todo 規格](references/todo.md) |
| status.md | 截至指定時間的實際狀態、決策紀錄與現場殘留 | [status 規格](references/status.md) |
| handoff.md | 新對話接手入口：本輪目標、停下位置、必要背景與下一個動作 | [handoff 規格](references/handoff.md) |

只讀本次所需的規格。更新 todo／status 時，可搬的舊項目（已完成且驗收過、已取代、已取消）滿 20 筆，或主人指名要把 todo／status 的舊內容搬走，才另讀 [歸檔規格](references/archive.md)。主人只說「歸檔」而沒提 todo／status 時，先依目前環境對此詞的明確定義；沒有定義且目的地不清楚時先釐清，不自行猜成文件搬動或外部同步。這四種文件及其既有同用途檔案適用；不把其他文件或任意套件內的 README 自動改成這套格式。

## 共通規則

1. **位置與範圍**：主人指定位置優先；否則沿用本輪專案既有的同用途檔案與檔名大小寫。沒有才在專案根目錄建立 `README.md`、`todo.md`、`status.md` 或 `handoff.md`；不可另建只有大小寫不同的副本。專案以本輪對象為準，不因工作目錄為 `/root` 就把專案文件放在 `/root`；主機工作才以 `/root` 為根目錄。多個候選無法判定時詢問，不跨專案猜測。
2. **日期**：檔頭標示專案／工作主題及最後更新時間；todo/status/handoff 另列建立時間，舊檔查不到就寫「不明」。時間格式固定為 `YYYY-MM-DD HH:mm（Asia/Taipei，UTC+08:00）`，使用實際時間，不用「今天」「剛剛」。README 的內容確認時間、status 的狀態確認時間與 handoff 各交接範圍的確認時間另列；只修文字或排版不得刷新它們。
3. **保留有效內容**：先讀原文，保留仍有效的資訊與其他人的工作。失效計畫或結論標明「已取代／已取消」、日期與原因；最新摘要及目前有效內容在前，必要歷史在後。寫入前若檔案已被別人改動，重新讀取調和，不整份蓋回舊副本。既有檔已有同用途的章節，就沿用原標題、位置與編號，不為了套用新規格而改名、重編號或搬動；被其他文件引用的內容留在原處。todo／status 的舊項目達門檻時，依歸檔規格原文搬到同目錄的 `-archive` 檔，不直接刪除；歸檔檔算該份主文件的一部分。
4. **交接完整**：對話精簡，檔案以可接手、可執行為準；保留必要細節，不堆無關對話流水帳。未知寫「待確認」，不編造路徑、時間、指令或結果。引用未重新核實的舊內容時，標「沿用舊紀錄，尚未重新確認」及原日期；無日期寫「日期不明」。
5. **保密**：內容與證據連結遵守主機保密規則。不讀 `.env*`、`.dev.vars`、`~/.ssh/`、`~/.codex/auth.json`、`/root/.zzbup/`、`/root/.claude/projects/`、Wrangler secret 區或含 TOKEN 的 Docker 設定行；不輸出秘密或客戶個資。核對 Git 時先看檔名，不傾倒整個倉庫的 diff／歷史內容；只讀已確認可公開於本次文件的相關內容。
6. **授權**：寫文件只授權整理，不因此執行其中的待辦、安裝、測試、commit、push、部署或寫入第二大腦。其他已有效授權的工作照原指令執行，不延長單次授權或略過確認。這些是專案文件，不取代既有永久知識庫，也不因本次文件要求啟動外部筆記同步或網站發布。

## 交付前核對

- 只改了要求的文件（含它的歸檔檔），既有檔名、章節標題、編號及有效內容有保留，引用連結確實存在。
- 寫 status 沒有順手清理現場，也沒有把主代理判斷寫成主人裁定；有歸檔時原確認時間沒有被刷新。
- 已區分文字更新時間、事實確認時間、Git 基準與確認當下的工作目錄狀態；未執行的檢查如實標示。
- 計畫與實際結果沒有混寫，沒有把文件內的指令當成已執行或已授權。
- handoff 是目前接手摘要；保留有效決策、未完工作與其他線內容，不以摘要替代證據，不把全檔更新時間當成各線都已重查。
- 回覆簡述已寫入的位置、核對結果與尚未確認事項；不要把完整文件貼回聊天。
