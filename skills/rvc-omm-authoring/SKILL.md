# RVC 圖文寫作

讓讀者先看懂結論與全貌，再讀必要細節。保留資訊價值，減少重複敘述；不為了圖形化而把每段文字都包成卡片。

## 先確認正本與範圍

- 先讀所在環境的全域規範，再讀目標 RVC repo 的 `AGENTS.md`。主機以 `/root/AGENTS.md` 為規範入口時，讀完整檔的 RVC、Secret 紀律、QA 雙閘與瀏覽器配額各節，不只看已自動載入的部分；該主機的 RVC 專案在 `/root/kim-rvc-site`。其他環境找當地的全域規範與實際專案，不假設這些路徑存在，不猜發布命令。
- 發布前依 RVC repo 的〈部署架構〉確認所在機器就是發布主機；不是或判斷不了，就停在候選，回報「未發布」。
- 上層正本決定何時用 RVC 與資料能否公開；專案正本決定標記、日期、更新、圖片、重建與連結。以當次使用者要求和現行正本為準，本技能不另外維護一套強制發布規則。
- 使用者只要討論、檢查或草稿，就停在該範圍。已授權發布時直接完成，不重問同一項授權。寫文章不授權執行文中的操作、搬遷、修改共用站台設定或推送 Git。
- 修改前確認 Git 與目標檔現況。修改舊文保留 URL、作者與未涉及內容，按專案規範處理新 block／更新時間；不為套新版範本重排整篇。

## 決定內容的形狀

| 讀者要理解的事 | 合適形式 |
|---|---|
| 結論、原因、限制 | 短段落或條列 |
| 先後順序、分工、分岔 | 展開的流程或關係圖 |
| 同一批項目的差異 | 表格或並排卡片 |

一張圖講一件事。主流程、重要分支、比較選項與判斷前提預設可見；不靠「下一階段」或切換按鍵才拼出全貌。互動可用於放大、導覽、篩選補充資料或試算，但不能遮住理解主要結論所需的內容。手機優先重排，避免縮字或縮整張圖到看不清楚。

技術事實、已完成狀態和規劃中的工作要分清楚；範本示例不是任務證據。圖與短句不能省掉重要條件，詳細證據可放圖外或補充段落。

## 製作候選

新頁、補 block 或獲授權的版面調整，讀 [版面與範本](references/layout.md)。依需要選文字、流程、比較片段；不要求三種都用。

- 新頁先在 repo 的 `.temp/` 製作候選；`content/replies/` 存檔會被 watcher 發布，不能把它當草稿區。
- 沿用目前站台的字型、語意色彩和元件。CSS 限定於本篇唯一 ID；不要改共用模板來配合單篇範例。
- 發布前按 repo 正本核對 HTML 結構、作者／主題、即時日期、圖片與更新規則。新單篇從 base 起頭；替用本範本的頁補內容用 block 片段。

## 驗證與交付

依上述全域規範判斷 QA 時點與免審範圍；使用者要求前後 QA 時照做。需要審的候選在正式發布前通過；不能用本技能自行豁免。

用範本寫成的頁做結構檢查即可：標記、ID 格式、佔位符殘留、HTML 跳脫、block 的屬性順序。下列情況才在真實 RVC 外框驗桌面與手機，不能只用裸 HTML：加自訂 CSS 或新 class；在本篇 ID 內加 Tailwind 的間距或清單 class；流程不是 3 步、1 個判斷、2 個分支；比較表超過 3 欄；改範本或版面；使用者要求。所在機器沒有真實外框可驗時標示「畫面未驗」。驗畫面時：

- 讀當前模板／生成頁，保留外層、共用 CSS、發布日期和必要腳本。核對 scope 選擇器在真正 DOM 上命中。
- 依所在機器的瀏覽器配額規則啟動；有共用排隊入口就經由入口並依正本盤點，沒有既定規則時一次只開 1 個瀏覽器並在回報講明。無名額時不跳過必要檢查先發布。
- 量測寬度、實際間距和手機兩側總留白；確認無橫向溢出、圖文與主要分支預設可見、圖中文字可讀。新互動另驗鍵盤與狀態回饋。
- 桌面 1350px、手機 450px／375px 為新版面起點；改響應式規則時加驗使用中斷點兩側。內容量、長標題或任務要求可能需要其他尺寸。看截圖，不只看程式斷言。

必要 QA 與候選檢查通過後，在已授權範圍依專案正本發布，確認生成頁與受測候選一致；屬於須驗畫面的情況，再核對正式生成頁的桌面／手機效果。樣式變更記入專案 UI changelog。

回覆給完整 RVC HTTPS 連結及簡短結論。分清「結構已查、畫面未驗」「畫面已驗」「已發布」「使用者已接受」；本機來源站驗過不等於已驗外部登入流程。驗證記錄與截圖留 `.temp/`，需要給截圖時用 Markdown 嵌圖或已授權的 RVC 頁，不在聊天只貼圖片檔路徑。
