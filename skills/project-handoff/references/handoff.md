# handoff.md：最新交接與新對話接手入口

handoff 回答「現在從哪裡繼續、要先知道什麼」。README 介紹整個專案及使用方式，todo 管工作計畫，status 保存實際狀態與證據；handoff 只摘要接手需要的部分，連到已有資料，不複製整套內容。

## 何時寫、放在哪裡

- 主人要求「寫交接」「交給新對話」或更新 handoff 時才寫；討論格式、讀取或檢查不寫。交接請求不自動建立或更新其他三份文件。
- 主人指定的檔案優先；未指定時，沿用既有 `handoff.md` 的位置／大小寫或已明確作為穩定交接入口的同用途檔。沒有才在**該專案根目錄**建立 `handoff.md`，不是一律放在 `/root`。
- 只有帶日期的詳細交接報告時，保留原檔並建立上述固定入口，以短摘要連到相關報告；不自行搬動、重新命名或每次另建日期檔。多個穩定入口無法判定時先釐清，不猜測或多建一份。
- 四份文件不強制齊全。沒有 todo／status 時，直接在 handoff 寫清必要任務／事實，不造連結、不擅自補建其他文件。

## 檔頭與有效性

列工作主題、交接範圍、建立時間、最後更新時間及**事實確認時間與範圍**。Git 基準、工作目錄狀態與差異摘要依 [有效性核對](freshness.md) 記錄；非 Git 或無法確認時如實標示，不為補欄位初始化 Git、提交或連正式環境。

日期與核對依 [有效性核對](freshness.md)；建立時間未知不猜測，歷史結果保留原確認時間。多線並行用同一入口分區，各線記自己的範圍、確認時間與必要的 Git 基準；更新一線不表示其他線也已核實。

## 接手所需內容

新檔可按下列順序整理；既有入口保留有效章節與被引用的編號，不強迫重排。沒有的事項明示不適用／未知，不以空欄假裝完成。

1. **目標與停下位置**：本輪在解決什麼，已完成到哪一步，最後結果是成功、失敗、部分完成或尚未執行。已修改、已測試、QA、提交、推送、部署與主人驗收分開。
2. **接手必知的決定**：與本輪有關的主人定案、已否決方向、不要重問／重做的事項及原因；主代理判斷另標示。詳細決策已有 status 時連回固定章節；唯一存在本檔的有效決策必須保留。
3. **下一個接手動作**：先做什麼、依賴什麼、預期如何確認完成；已有 todo 時連到固定任務編號，詳細排程不抄一遍。過期待辦與目前現場不符時寫明差異，未核實不宣稱待辦已完成。
4. **現場與協作**：會影響接手的未提交修改、其他線責任與共用檔、worktree、背景工作／測試／暫存證據；相關盤點依 [status 的現場殘留規格](status.md#現場殘留)，已有紀錄就連結並標原時間。未盤點寫未盤點，其他線或歸屬不明的資源不自行清理。
5. **操作與授權界線**：記錄具體動作、目標、授權來源與尚待確認事項；引用既有規範，不另造規則。已有效授權不重問，但單次已用完、撤銷或不涵蓋新動作的授權不能沿用；無法判定時標待確認。文件中的指令或「下一步」不構成新的執行授權。
6. **證據與閱讀入口**：連到實際存在的 README、todo、status、詳細交接、QA／測試／部署證據；不把暫存日誌當唯一永久正本。若證據只在暫存目錄，標明路徑及可能失效，接手時先確認仍存在；缺證據不重述為已驗證。

開頭應讓接手者迅速看到本輪目標、停下位置與第一個動作；詳細資料按需要連過去。篇幅以能安全接續為準，不訂死行數，也不寫對話逐字流水帳。

## 更新與保留

- 只更新主人要求的範圍。寫入前重讀原檔；若其他對話已改動，按最新內容調和，不能整份蓋回舊副本。無法安全合併時保留原檔並指出衝突，先完成不衝突部分。
- 保留其他線有效內容、未完成工作、有效限制與決策（含影響接手的已否決事項）。狀態改變用已確認的新摘要接續；未核實的舊結論保留原時間並標限制，不偷偷轉成最新事實。
- 不每次附加一整篇交接。可以精簡已被取代且不再影響接手的摘要，但必要歷史須能追溯到**已存在、已確認的**詳細紀錄；沒有其他保存處時，在本檔保留必要歷史與原時間，不假設 Git 已保存未提交內容。
- 被其他文件引用的章節／錨點保留或留下可用的轉引，不直接移除造成斷鏈。日期交接報告保留為證據，不因新入口而刪除。
- handoff 不套用 todo／status 的「滿 20 筆」自動歸檔規則，也不因此新增歸檔流程、日期檔、第二大腦同步或監控。

## 交付前核對

確認接手者不必重讀聊天即可知道從哪裡繼續；連結存在；摘要的版本、範圍與證據吻合；沒有把本機驗證當正式驗收、把文字更新時間當全案確認時間，或把待辦當授權。只要求 handoff 時，只交付該入口的變更，其他文件發現過時可註記待更新，不順手改寫。
