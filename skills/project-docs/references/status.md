# status.md：截至指定時間的實際狀態

先遵守 SKILL.md 的共通規則。檔頭列專案／工作主題、建立時間、最後更新時間；舊檔建立時間不明就如實寫「不明」。

新建檔的內容順序：檔頭與整體進度 → 分組狀態 → 證據與限制 → 決策紀錄 → 現場殘留 → 下一個接手動作。既有檔已有同用途章節（例如〈主人已決定〉）就沿用原標題、位置與編號，新內容寫進原章節，不另開一節。

status 是實際狀態、決策與現場紀錄；[handoff](handoff.md) 只擷取接手必要摘要及其對下一步的影響，再連回這裡的證據。兩者內容有衝突時依 [有效性核對](freshness.md) 查證，不因 handoff 更新較晚就推翻 status，也不因 status 是狀態文件就忽略已確認的新證據。只要求 status 就不更新其他文件。

主人的決定與等主人處理的事以本檔為家：交接組指令也會寫進這兩類（見 [SKILL.md 的分組指令](../SKILL.md#分組指令)），todo、handoff 只連過來。更新本檔不必為此去讀 handoff。

## 檔頭與分組

- 另列**狀態確認截至**：實際確認時間與確認範圍，再用一句話說明整體進度。各事項確認時間不同時逐項標註；只調整文字不把舊確認時間改成現在。
- 分開列「已完成」「進行中」「尚未開始」「受阻／待確認」，清楚說明實際做到哪一步、剩下什麼及阻塞原因；不存在的類別可以省略。

## 證據與限制

- 依工作性質記錄實際驗證結果、已知問題與必要證據連結。程式工作分清**已修改、已測試、已通過 QA、已 commit、已 push、已部署、主人已驗收**，未執行、失敗或無法確認的項目須明說，不統稱完成。
- 紀錄本次測試／部署時間及工作主機、測試環境或正式環境；不能把舊結果當成本次驗證。建置或測試通過不等於已完成實際畫面驗收。
- 保留影響交接的限制及必要環境／版本資訊；決策依下方〈決策紀錄〉記錄。Git 相關事實依 [有效性核對](freshness.md) 記錄基準、確認範圍與當下工作目錄狀態；不把來源 SHA 當成已部署的證據。
- 沿用舊文件但未重新核實，標「沿用舊紀錄，尚未重新確認」及原紀錄日期；沒有日期寫「日期不明」。已知過時直接標明，不只刷新檔案日期。
- 已完成事項與舊驗證紀錄達門檻時，依 [歸檔規格](archive.md) 搬到歸檔檔，不直接刪除。

## 決策紀錄

接手者最常把已經否決的做法再提一次，所以決定與原因要留在 status，不只留在對話。沒有決策可記就省略本節。

- 分「已定案」與「已否決」兩組。每筆寫：決定了什麼、日期、誰決定、一句原因。已否決的另寫主人說過的重提條件；沒說就寫「未說明」，不代擬。
- **主人裁定**與**主代理判斷**分開標示，不把自己的判斷寫成主人裁定。主人的話貼近原意記錄，不加碼、不延伸到沒講到的範圍。
- 決定被推翻時，原筆標「已推翻」、日期與原因，新決定另列一筆；不改寫或刪除原筆。決策紀錄不歸檔，已否決的做法再舊也留在主文件。
- 只放本專案這一輪工作的決定。跨專案或長期有效的規則屬於 AGENTS.md 與 永久知識庫 正本，新寫入時只連過去、不複製，也不因此啟動第二大腦同步。既有檔裡已被其他文件當成正本引用的內容照舊保留。
- 還沒決定的事不放這裡：一律在「受阻／待確認」列一行，含等主人看片、驗收、裁決的事；todo、handoff 只連過來。
- 採用時：提案或排任務前先讀本節。要重提已否決的做法，須先說明哪個前提變了，由主人決定，不自行翻案。

## 現場殘留

列出**本專案**這一輪工作留在主機或環境上、接手者會碰到的東西；不盤點別的專案或全機。每次寫 status 都要列本節：確認沒有才寫「無」並附確認時間，沒盤點的類別寫「未盤點」，不能用「無」代替。專案沒有這類現場（例如非程式專案）時，整節寫一行「不適用」。舊檔沒有本節時視同未盤點。

- 盤點類別：
  - 未收掉的 worktree（獨立工作目錄）：路徑、分支、有無未提交變更。
  - 未推送或未合併的分支：分支名、領先遠端幾筆。未提交／未追蹤的檔案沿用工作目錄狀態的紀錄，不重複列。
  - 仍在執行的背景工作與本機伺服器：用途、PID、port、怎麼停。
  - 測試環境目前的版本：〈證據與限制〉已有本次部署紀錄就連過去；沒有就寫「未確認」。
  - 暫存檔與中間產物：位置（例 `.temp/`）及是否還需要。
- 每項寫明：是什麼、在哪、誰留下的。本輪自己留下的才寫可否收掉與收掉的方法；盤點時看到屬於本專案、但不是本輪留下的，只標「其他對話」或「歸屬不明」，不替它判斷能不能收，也不猜。
- **只記錄，不清理**：寫 status 不授權移除 worktree、停程序、刪檔或釋放鎖；清理照原有授權另行處理。
- 盤點只用唯讀查詢（例 `git worktree list`、`git branch -vv`）。程序只列 PID、程序名與 port，不讀也不輸出完整命令列或環境值；不為盤點動用憑證或連到別臺機器。看不到全機程序時寫「視野不足」，空清單不等於沒有。
- 本節另列自己的確認時間。現場變得比程式碼快：接手後要依賴哪一項，就先重查那一項，不把舊紀錄當現況。
